# Project Rules

## Scope
- ทำกราฟิกสำหรับเสื้อสกรีน; ส่งเฉพาะภาพ/ชิ้นงานที่ผู้ใช้สั่ง
- ภาพแนบของผู้ใช้เป็น Source of Truth ตามบทบาทที่ระบุ การแก้ภาพต้นฉบับให้ล็อกทุกส่วนที่อยู่นอกขอบเขตแก้
- ก่อนแก้ให้ตรวจว่าอะไรอยู่ใน scope; ห้ามเพิ่มหรือเปลี่ยนส่วนอื่น

## Approval Gates
- ทำงานเป็น 3 ระยะ เรียงตาม Quest; หลังแต่ละระยะ QA ตรวจและ PM ส่งตัวเลือกให้ผู้ใช้เลือกก่อนเริ่มระยะถัดไป
- ระยะ 1 เลือกแนวภาพ เทียบวิธีวาดคน รูปทรงและน้ำหนักดำบนฉากเต็ม โดยถอดแนวจากภาพอ้างอิงมาเป็นตัวเลือกขาวดำ
- ระยะ 2 ทำ composition ตาม brief 7 แบบ ด้วยลายเส้นที่ผู้ใช้เลือก; ยังไม่สรุปสี
- ระยะ 3 เสนอวิธีลงสีบน composition ที่เลือก ใช้ไม่เกิน 2–3 สีบวกพื้นขาวตาม brief
- ห้ามข้ามการเลือกของผู้ใช้หรือทำหลายระยะรวมกัน

## Visual QA
- ตรวจ anatomy: ท่ายืน/นั่ง การถ่ายน้ำหนัก มุมหัน แขน ขา มือ นิ้ว เท้า และจุดสัมผัสวัตถุ
- ตรวจความครบถ้วนของวัตถุ; วัตถุชื่อเฉพาะต้องมีภาพถ่ายอ้างอิงก่อนวาด
- ยึด Graphic Design, รูปทรงชัดและทำซ้ำได้บนงานพิมพ์; ไม่ทำภาพแนว animation
- ตรวจจำนวนสี ความชัดเมื่อย่อ ตัวหนังสือ และไฟล์ PNG ตามระยะงาน

## Project Manager
- PM เป็นช่องทางเดียวระหว่างผู้ใช้, Designer และ QA
- PM มอบหมาย scope/เกณฑ์ให้ Designer → ส่ง QA ตรวจอิสระ → ส่งรายการแก้กลับ Designer จน PASS
- QA ผ่านแล้ว PM ส่งเฉพาะผลของระยะปัจจุบันให้ผู้ใช้เลือก; หยุดจนได้รับตัวเลือกก่อนระยะถัดไป
- ห้ามเริ่มงานจาก Queue ที่ไม่ได้รับมอบหมาย

## Department และ Queue
- Designer เป็นเจ้าของภาพต้นฉบับใน `output/`; แก้เฉพาะรายการ QA
- QA อ่านไฟล์ของ Designer และเป็นเจ้าของรายงานใน `Context/qa/`; QA ไม่แก้ภาพเอง
- คิวอยู่ใน `Context/quests/<department>/`; PM ส่งต่องานระหว่าง Department
